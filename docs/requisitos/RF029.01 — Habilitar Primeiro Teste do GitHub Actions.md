# RF029.01 — Habilitar Primeiro Teste do GitHub Actions

Projeto: DSV RFID System
Requisito: RF029.01
Tipo: Ajuste do RF029
Prioridade: Alta
Branch: feature/RF029-github-actions

## 1. OBJETIVO

Habilitar temporariamente a execução do workflow
GitHub Actions na branch de desenvolvimento RF029.

Atualmente, o workflow utiliza somente:

    workflow_dispatch

Como ainda não está presente na branch padrão
do repositório, não aparece na página Actions
para execução manual.

Precisamos permitir o primeiro teste sem realizar
merge na main.

## 2. ARQUIVO A MODIFICAR

Modificar exclusivamente:

    .github/workflows/build-windows.yml

Não criar outro workflow.

Não alterar os scripts de compilação.

## 3. ALTERAÇÃO NECESSÁRIA

Localizar:

    name: Build DSV RFID Windows

    on:
      workflow_dispatch:

Substituir por:

    name: Build DSV RFID Windows

    on:
      workflow_dispatch:

      push:
        branches:
          - feature/RF029-github-actions
        paths:
          - ".github/workflows/build-windows.yml"

IMPORTANTE:

Preservar o evento workflow_dispatch.

O evento push será temporário e deverá funcionar
somente quando o próprio arquivo do workflow
for modificado na branch RF029.

Não adicionar execução automática para main.

Não adicionar execução para todas as branches.

Não adicionar pull_request ou outros eventos.

## 4. PRESERVAR AS CONFIGURAÇÕES EXISTENTES

Não modificar:

- permissions: contents: read
- concurrency
- cancel-in-progress: false
- runs-on: windows-2022
- timeout-minutes: 30
- Python 3.12 x64
- Checkout
- persist-credentials: false
- SHAs das Actions
- Instalação das dependências
- Testes automatizados
- Build Windows
- Verify Windows
- Auditoria de distribuição
- Empacotamento ZIP
- SHA-256
- Upload do artifact
- Retention-days: 7

Preservar todas as configurações de segurança
implementadas no RF029.

Não adicionar permissões de escrita.

Não adicionar tokens ou secrets.

## 5. SEGURANÇA

O workflow deverá continuar utilizando:

    permissions:
      contents: read

Não permitir:

- Commit automático.
- Push automático.
- Merge automático.
- Publicação de releases.
- Deploy.
- Alteração de configurações do GitHub.
- Upload de arquivos .env reais.
- Publicação de credenciais.

Não executar código de branches não confiáveis
com permissões elevadas.

O GitHub Actions deverá apenas compilar,
testar e disponibilizar o executável.

## 6. VALIDAÇÃO LOCAL

Antes de finalizar:

1. Ler AGENTS.md.
2. Verificar a branch atual.
3. Executar git status.
4. Preservar alterações locais existentes.
5. Modificar somente o workflow indicado.
6. Validar a sintaxe YAML.
7. Confirmar a presença de workflow_dispatch.
8. Confirmar a presença do novo evento push.
9. Confirmar que o filtro de branch é exato.
10. Confirmar que o filtro paths é exato.
11. Verificar o diff final.

Não executar git reset ou git clean.

Não modificar outros arquivos sem necessidade.

## 7. RESULTADO ESPERADO

Após o usuário realizar commit e push
na branch:

    feature/RF029-github-actions

O GitHub deverá iniciar automaticamente
o workflow:

    Build DSV RFID Windows

O workflow deverá executar:

1. Checkout.
2. Configuração Python.
3. Instalação de dependências.
4. Testes sem hardware.
5. Build Windows.
6. Verificação do executável.
7. Auditoria e empacotamento.
8. Upload do artifact.

Se aprovado, o pacote deverá aparecer como:

    DSV-RFID-Windows

Não afirmar que o build foi aprovado antes
de uma execução real no GitHub.

## 9. APÓS O PRIMEIRO TESTE

IMPORTANTE:

O gatilho push é temporário.

Após a primeira execução bem-sucedida,
o usuário deverá solicitar sua remoção.

O workflow deverá voltar a utilizar somente:

    on:
      workflow_dispatch:

Depois da revisão e integração do RF029
à branch padrão, as compilações poderão
ser iniciadas manualmente pela interface
GitHub Actions.

Não remover o gatilho temporário agora.
